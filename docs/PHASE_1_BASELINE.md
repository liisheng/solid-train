## Executive result

The project runs locally on the RTX 4070 SUPER. The selected baseline has exactly
**49,295,872 trainable parameters**, including the one tensor shared by the input
embedding and output head. The independently derived total agrees with enumeration of
all 110 unique trainable tensors and is **704,128 parameters below** the official
50,000,000 cap.

The final automated suite passes **5/5 tests**. A bounded full-model CUDA check passed
model construction, one forward/backward pass, one optimizer step, temporary checkpoint
save/load, generation, and both ordinary and rolling `lm-evaluation-harness`
log-likelihood calls. No full benchmark or long training run was started.

Phase 1 found and fixed two clear baseline problems:

1. Checkpoints did not preserve Python, NumPy, PyTorch, CUDA, or dataset-sampler RNG
   state. New format-version-2 checkpoints preserve those states; an exact continuous
   versus resumed CPU regression test passes. Existing pilot checkpoints remain legacy
   format and cannot be resumed exactly.
2. The data script and guidance still recommended TinyStories. The TinyStories paper
   identifies it as synthetic text generated by GPT-3.5 and GPT-4, which conflicts with
   this project's stricter prohibition on commercial model-generated training data.
   The local default and README now use the actual FineWeb-Edu pilot, and the research
   plan marks TinyStories ineligible for this project.

The result is “PASS WITH RISKS,” rather than an unqualified pass, because participant
eligibility is a personal attestation, current pilot checkpoints predate the RNG fix,
the final dataset/tokenizer/decontamination lock does not yet exist, and required final
AI-assistance and dataset disclosures are incomplete.

## 4. Exact selected architecture and parameter audit

The selected model is a decoder-only, pre-norm causal Transformer with RoPE,
RMSNorm, SwiGLU, PyTorch scaled dot-product attention, bias-free projections, and a
tied input embedding/output projection.

| Field | Value |
|---|---:|
| Vocabulary | 16,384 |
| Maximum sequence length | 1,024 |
| Layers | 12 |
| Residual width | 512 |
| Attention heads / KV heads | 8 / 8 |
| Head dimension | 64 |
| SwiGLU hidden width | 1,536 |
| RoPE theta | 10,000 |
| RMSNorm epsilon | 1e-5 |
| Dropout | 0.0 |
| Linear biases | None |
| Embedding/output tying | Yes |
| Unique trainable tensors | 110 |

### Independent count

| Trainable group | Calculation | Parameters |
|---|---|---:|
| Tied token embedding and output head | 16,384 × 512 | 8,388,608 |
| Attention projections | 12 × (Q + K + V + O) × (512 × 512) | 12,582,912 |
| SwiGLU projections | 12 × 3 × (512 × 1,536) | 28,311,552 |
| Two block RMSNorms per layer | 12 × 2 × 512 | 12,288 |
| Final RMSNorm | 512 | 512 |
| **Total** | sum of every unique trainable tensor | **49,295,872** |
| Official cap margin | 50,000,000 − 49,295,872 | **704,128** |

The conceptual output head uses `F.linear(x, token_embedding.weight)` and therefore
adds no second tensor. Counting the shared tensor once is correct; omitting it would
not be. The RoPE cosine/sine tables are non-trainable, non-persistent buffers. There
are no learned positional embeddings or biases.

Enumeration independently produced this grouping:

- tied embedding/output: 8,388,608;
- attention: 12,582,912;
- feed-forward: 28,311,552;
- block norms: 12,288;
- final norm: 512.

Both the formula and direct enumeration equal 49,295,872.

## 5. Random initialization and eligibility audit

Technical from-scratch eligibility is confirmed for the current source path:

- `TinyBenchLM(config)` accepts only a local numeric configuration, not a model name or
  weight path.
- Every linear and embedding weight is initialized locally from a normal distribution
  with standard deviation 0.02. Attention output and feed-forward down projections are
  then initialized with the residual-scaled standard deviation `0.02 / sqrt(2L)`.
- RMSNorm weights start at one. RoPE tables are calculated locally and are not
  trainable.
- `train.py` loads weights only when the operator explicitly supplies `--resume`.
  Generation and evaluation load a user-specified local checkpoint as expected.
- Repository-wide search found no `from_pretrained`, transformer-model import, hosted
  inference client, teacher model, distillation loss, pruning/merging source, or remote
  weight fetch.
- The tokenizer is trained locally from the selected text with the `tokenizers`
  library; it is not a pretrained tokenizer.

No paid service, hosted inference API, cloud compute, pretrained model weight, or model
generated training text was used in Phase 1. TinyStories was removed from defaults and
future recommendations after the primary
[TinyStories paper](https://arxiv.org/abs/2305.07759) confirmed that its stories were
generated by GPT-3.5 and GPT-4.

This code audit establishes the eligible training path. It does not cryptographically
prove the complete provenance of old binary checkpoints; the lack of an initial Git
commit and artifact hashes is recorded as a risk.

## 8. Problems fixed in Phase 1

### Reproducible checkpoint resume

New checkpoints now record a format version and preserve:

- model and optimizer state;
- Python `random` state;
- global NumPy state;
- PyTorch CPU RNG state;
- every CUDA RNG state; and
- independent training and validation `numpy.random.Generator` states.

Resume restores these after model/optimizer construction. Loading a legacy checkpoint
prints a clear warning that the resume is functional but not exact. A regression test
proves exact next-step equivalence on CPU, and the CUDA smoke proves format-2 state can
be saved, loaded to CUDA, and round-tripped exactly.

### Synthetic-data constraint

The data-preparation default, README pilot command, paths, and research-plan guidance
were corrected to match the actual FineWeb-Edu pilot and the user's ban on commercial
model-generated training data. TinyStories remains cited only as research that explains
small-model behavior; it is explicitly excluded as a training source.

## 9. Known risks and deferred work

1. **Participant eligibility cannot be machine-verified.** The user must attest student
   status, age, team membership, and one-track participation.
2. **AI-assistance disclosure is incomplete.** The official rules require Codex and any
   other AI tool to be listed in the final README and Built With section.
3. **No Git baseline exists.** The repository has no commit and all project files are
   untracked. Phase 1 intentionally did not commit, but this weakens provenance and
   change auditing until the user creates an approved baseline commit.
4. **Existing pilot checkpoints are legacy.** They predate RNG/sampler capture. New
   checkpoints are reproducible; old ones are not exactly resumable.
5. **Pilot tokenizer/model mismatch.** The current full model has a 16,384-token input
   and output space but the pilot tokenizer has only 8,192 tokens. Half the embedding
   rows can never be input tokens, and output IDs outside the tokenizer vocabulary may
   not decode. This is acceptable only for engineering smoke tests.
6. **Final data is not locked.** There is no final mixture, immutable revision list,
   source/license manifest, checksum manifest, quality audit, or benchmark
   decontamination report.
7. **Remote dataset revision is unpinned.** Re-running the current preparation command
   later may not reproduce byte-identical documents if the hosted dataset changes.
8. **Official WikiText-103 slice/settings are not locally specified.** The repository's
   `paloma_wikitext_103` task is only a development proxy. Organizer-provided holdout and
   settings must be frozen before final scoring.
9. **Exact evaluation protocol is not locked.** Current evaluation uses zero-shot tasks,
   but final task versions, metric names, normalization, few-shot counts, and harness
   revision need an organizer-aligned lock.
10. **Final compute reporting is absent.** The training loop records step time,
    throughput, and peak allocated VRAM, but final elapsed time and approximate total
    compute still need a defined method.
11. **Dependencies are range-specified.** The verified environment is recorded above,
    but a fresh installation can resolve newer packages unless a lock file is added.
12. **Final submission artifacts do not exist.** Final scores, README disclosures,
    screenshots, public repository, demo video, and Built With list are later-phase work.

These are Phase 2 or submission risks, not reasons to invalidate the working Phase 1

## 14. Research-plan deviations

Phase 1 treated `docs/RESEARCH_PLAN.md` as guidance, not authority.

- **TinyStories was excluded.** The earlier plan proposed a minority TinyStories
  component, but the primary paper says GPT-3.5 and GPT-4 generated the stories. That
  conflicts with the user's no-commercial-model-generated-data constraint.
- **No additional architecture/data experiments were run.** The independent count and
  existing pilot evidence were enough to lock the baseline; experiments belong after
  the rules and data are frozen.
- **No full benchmark was run.** Structural adapter checks and the existing five-item
  ARC smoke were sufficient for Phase 1 and avoided an expensive evaluation.
- External research was deliberately limited to the official competition pages, the
  TinyStories primary paper needed to resolve the synthetic-data conflict, and the
  FineWeb-Edu dataset card needed to verify the current pilot identifier/license.

This narrower approach preserves Phase 1's purpose: a trustworthy baseline and rules
lock, not early entry into data curation or long training.
